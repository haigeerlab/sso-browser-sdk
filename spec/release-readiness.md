# release-readiness：首版发布范围与证据收口

## 目标

把已有 OIDC、CAS、SAML 以及 Vue/React/Vite 宿主的验证结果汇总为可审阅的首版发布候选方案。明确对外承诺的协议、包接口、宿主版本和后端前提；逐项处理未验证或有风险的地方，形成可复现的发布检查与接入文档。此模块决定是否达到发布门槛，实际向 npm 或私有仓库推送包是单独的最终动作。

## 首版拟定范围

- 一个无 Vue/React 运行时依赖的 ESM + TypeScript 声明包；根入口 `createSSO`，按需选择 `/oidc`、`/cas`、`/saml`。三个协议都采用**宿主后端处理协议并创建本域会话**的模式。SDK 不直接接收令牌、断言或票据。
- 已实测宿主基线为 Vue 3.4.0、React 19.3.0、Vite 5.0.0、Node 22.22.0；只对实测组合给出兼容声明。Webpack 暂缓。WS-Fed 与 Negotiate 虽有入口和单测，尚无真实协议互操作，不列入首版“已验证协议”承诺；是否从首版包导出移出或标成实验能力，应在发布审查时确定并用包测试锁定。
- 本域会话查询、登录导航、刷新恢复、错误状态、手动重试与本域登出属于 SDK 承诺。全局单点登出、跨源会话接口、完整 SSR、所有浏览器/路由库、生产 IdP/SP 互通不在现有证据的承诺内。

## 发布审查内容

1. **证据矩阵**：逐项链接单元、简版交互、独立协议互操作、tarball 隔离安装和真实浏览器记录；注明版本、命令、通过/失败、与生产环境的差距。补齐可识别版本的浏览器测试，至少复测首版代表流程；参考后端只证明本机互操作。
2. **包与 API**：审查对外 `exports`、类型、`files`、运行时依赖、包名、版本、许可证、Node/浏览器支持范围、README 示例；用 `npm pack --dry-run` 和从实际 tarball 安装验证。测试服务、私钥、证书和示例不得进入包。将 `private` 原型变为可发布包前，先确定 registry、包名和版本策略。
3. **宿主后端清单**：给业务方一份按协议选择的最小接口、回调、Cookie、CSRF、回跳限制、错误语义与协议安全校验清单；同时列出 SDK 可配置项和不可由前端弥补的后端缺失。至少有一个真实业务宿主与实际认证中心的端到端验收，才可把“生产接入已验证”写进发布结论。
4. **安全与依赖**：重新运行依赖审计，核对告警是否影响发布包运行时或只在 Vite 5 测试/构建链；在保持用户指定 Vite 5.0.0 兼容的前提下给出处置或明确风险接受记录。复核回跳、安全 Cookie、协议校验边界和测试私钥不入包。
5. **发布可复现性**：固定完整回归和 tarball 检查命令、变更记录、版本号及发布清单。若仓库尚无 Git/CI 或目标业务环境不可用，明确列为发布阻断项，不以本机测试自动宣布稳定版。

## 需要业务方确认的外部条件

- 发布目标：npm 公共仓库、私有 npm registry，或先交付本地 tarball；以及正式包名/命名空间、版本号与发布权限。
- 首个真实业务宿主和认证中心环境；后端需提供按所选协议的接口与回调、测试账号、HTTPS/Cookie/反向代理拓扑，供生产前联调。
- 对 WS-Fed、Negotiate 的首版处理：移出对外导出，还是保留并明确标成未验证实验入口。建议首版正式支持声明仅含 OIDC、CAS、SAML。

## 验收标准

- 发布候选文档能让接入方按协议选择配置，明确前后端各自职责、支持矩阵和不支持范围；所有“已验证”声明都能追溯到可复测记录。
- 完整回归、打包内容、类型与隔离安装再次通过；依赖审计结果和处置可查；候选包没有测试服务或敏感材料。
- 对包名/registry/版本、真实宿主联调、浏览器版本和 Git/CI 等发布前条件给出明确结论：通过、待办或风险接受。未达门槛时输出候选版和阻断清单，不宣称稳定发布。
- 实际发布前提供可审阅的准确 tarball、版本与发布目标；由用户确认最终发布动作。
