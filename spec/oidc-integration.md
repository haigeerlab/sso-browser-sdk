# oidc-integration：宿主后端 OIDC 登录

## 目标

业务应用使用同一 SDK 包的 OIDC 入口，在已有宿主后端和统一认证中心之间完成一次登录、跨宿主复用中心会话、恢复原页面及本域登出。首版采用宿主后端执行 Authorization Code + PKCE 的模式；浏览器 SDK 不接收授权码或持有令牌。

## 三方职责

| 参与方 | 必须提供或完成 |
| --- | --- |
| 认证中心 | OIDC 发现文档、授权与令牌端点、签名公钥、已登记客户端和精确回调地址；使用独立的中心会话 Cookie。若要求首次进入第二个可信业务应用完全无交互，中心还需明确第一方客户端的同意策略。 |
| 宿主后端 | 登录入口、回调入口、会话查询和本域登出；生成并验证 `state`、`nonce`、PKCE S256；向中心交换授权码并校验 ID Token 的签名、签发者、受众、时效及主体；创建 HttpOnly 本域会话、限制回跳地址并保护业务 API。 |
| 前端 SDK | 查询本域会话；未登录时顶层导航到同源宿主登录入口并传入目标页面；回到应用后恢复状态；区分用户未登录、认证失败和宿主/网络错误；调用本域登出。 |

## 前端配置与流程

1. 业务方导入 `/oidc` 的 `oidcAdapter`，配置同源 `loginEndpoint`；已有查询参数可保留，回跳参数名称默认为 `returnTo`，可通过 `returnToParam` 适配宿主接口。
2. SDK 的 `ensureAuthenticated` 先调用宿主会话接口。未登录时将同源目标地址传给适配器，并导航到宿主登录入口；SDK 不直接拼接认证中心授权请求。
3. 宿主后端重定向至认证中心；认证中心利用自己的 Cookie 判断是否需要登录。成功后浏览器返回宿主回调，宿主完成换码和身份校验，设置本域 Cookie，再重定向到目标页面。
4. 应用重新加载后 SDK 查询宿主会话并进入 `authenticated`。访问第二个已登记宿主时可复用中心会话；是否额外显示授权同意页由认证中心策略决定。
5. `logout` 默认只注销当前宿主会话；中心登出或全局单点登出属于额外后端能力，不作为此模式默认保证。

完整交互时序及后端边界见 [方案调研](../docs/SSO_SDK_方案调研.md) 的 OIDC 流程图。

## 失败与安全边界

- SDK 拒绝跨域回跳目标和跨域宿主登录入口；宿主后端也必须独立限制 `returnTo`，不能依赖前端校验。
- 错误、取消、过期或非法回调不得建立本域会话。宿主后端应将失败转换为可供业务页面或会话接口识别的结果；SDK 不把故障当成访客反复跳转。
- 回调 `state` 不符、授权码重放、PKCE 或 ID Token 校验失败时，宿主后端拒绝建立会话。
- 中心会话过期后，再访问未登录的宿主应重新进入中心登录；已建立的其他宿主本域会话是否继续有效由后端会话策略决定。
- 浏览器 SDK 不读取中心 Cookie、不注入其他域名 Cookie、不在前端持久化 OIDC 令牌。

## 验收标准

- Vue App A 首次登录后，React App B 在同一浏览器内使用中心会话完成登录；两个宿主各自拥有独立本域会话。对已约定的可信第一方客户端，测试环境无第二次登录或同意操作。
- 自动化测试在真实 OIDC 参考实现上完成发现、授权码 + PKCE、令牌交换与身份校验，并覆盖无效 `state`、回调重放和本域登出后的恢复。
- 浏览器测试覆盖首次登录、跨宿主登录、本域登出及恢复，并明确记录认证中心版本与开发专用配置。
- 补测中心会话过期后的重新登录，以及错误/取消回调在业务页面的可见反馈；这些未通过前，不宣称 OIDC 完整异常路径已验收。
- 参考实现与简版夹具均不等于生产认证中心或真实业务宿主验收。兼容范围和剩余风险应在发布准备模块明确列出。
