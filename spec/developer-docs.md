# developer-docs：开发者文档与接入验收

## 目标与范围

按已确认的 [ADR-001](../docs/decisions/001-developer-documentation.md) 交付中文 VitePress 文档站、SDK 包 README 和仓库 README，使首次接入者能判断后端前提、安装真实包产物、按框架和协议完成后端会话接入。

覆盖开始使用、原生 TypeScript/Vue/React、五种协议、后端 HTTP 契约、Demo、API、部署排错和支持矩阵。OIDC/CAS/SAML 只声明已有本机验证；WS-Fed/Negotiate 保留实验状态。认证协议由宿主后端处理，不改变 SDK API，不新增生产后端或发布 npm 包。

## 交付要求

- 私有工作区 `apps/docs`，Markdown 静态站、中文导航、本地搜索、代码复制和移动阅读；根目录提供开发/构建/预览命令。
- 示例使用实际 SDK 导出，可执行而非仅有未定义占位函数；站点从源文件导入关键片段。
- 当前安装走源码构建和 tarball，不宣称原型已发布；明确业务契约路径与参考服务实际路径。
- 完整解释状态、自动导航的返回值、手动重试、回调错误展示和本域退出；不给全局登出、跨源或生产互操作作未经验证的承诺。
- 协议页包含后端参数、请求/响应、前端配置、Demo 路径和证据；沿用现有参考后端。
- README 与站点一致，站点依赖和示例不进入 SDK npm 包。

## 验收

1. 文档构建与链接检查通过，根路径和仓库子路径均能预览；搜索和移动导航由浏览器验证。
2. 实际 tarball 隔离安装后，页面引用的 TS/Vue/React 示例类型检查和构建通过；五个适配器配置经过运行验证。
3. 按文档所述路径连接独立 OIDC/CAS/SAML/WS-Fed 参考后端，验证会话建立、恢复、本域退出和失败重试；Negotiate 企业域缺口明确记录。
4. 已有 SDK 全量回归通过，包内容和宿主依赖版本未被文档工作区改变。
5. 形成首次使用者视角的审阅记录，区分已验证、待环境和已确认缺陷。源码缺陷单独记录，不通过文档隐藏。
