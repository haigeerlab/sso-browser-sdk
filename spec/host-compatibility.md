# host-compatibility：Vue、React 与 Vite 宿主接入

## 目标

验证同一个框架无关的浏览器 SDK npm 包，能够由 Vue 3.4.0 与 React 业务宿主按公共配置接入，在 Vite 5.0.0 开发与构建环境中完成登录、会话恢复、错误反馈和本域登出。结论应基于实际安装的包和浏览器运行，而非仅依据 monorepo 工作区的源码引用或构建成功。

## 已知约束与本 Spec 假设

- 用户明确指定兼容 Vue 3.4.0、Vite 5.0.0，暂不考虑 Webpack；React 未指定最低版本。本模块以当前锁定的 React 19.3.0 作为实测点，不据此承诺完整 React 版本范围。
- 宿主各自已有后端；SDK 沿用 OIDC、CAS、SAML 三个已验证的后端会话模式，不在本模块新增协议实现。
- 首版依赖 ES module、现代浏览器和同源宿主会话接口；SSR 仅要求 SDK 模块可安全导入，服务端实际登录导航和框架 SSR 集成需要单独需求。
- 路由库不是 SSO 必需依赖。用 Vue/React 的最小入口接线和受保护页面示例说明调用时机；若业务使用路由守卫，可依公共 API 接入，但不把某个 Router 版本变成 SDK 的运行时依赖。

## 接入与包边界

1. 业务方安装同一 `sso-browser-sdk-prototype` 包；根入口导入 `createSSO`，按后端协议从 `/oidc`、`/cas` 或 `/saml` 导入一个适配器。Vue 和 React 不需要各自的协议包或 SDK 核心副本。
2. 每个宿主配置本域 `session.endpoint`、`logout.endpoint`、同源 `loginEndpoint`；后端会话响应有差异时使用 `session.map`，回跳参数名有差异时使用 `returnToParam`。安全校验仍由宿主后端完成。
3. 示例应在应用入口或受保护页面调用 `ensureAuthenticated()`，订阅状态、在卸载时取消订阅；主动登录使用 `login()`，本域登出使用 `logout()`。避免渲染期间导航、重复触发和将 `401` 与网络错误混淆。
4. 发布包仅含 ESM JavaScript、类型声明和协议子路径导出；不得把 Vue、React、Vite、测试后端、证书或私钥作为 SDK 运行时依赖或包内容。

## 验证方法

- 从 `npm pack` 产物而非工作区软链接安装到隔离的 Vue 3.4.0 / React 宿主，核对实际解析的根入口、`/oidc`、`/cas`、`/saml` 与类型声明；在 Vite 5.0.0 中运行开发服务器和生产构建。
- 在真实浏览器验证首次登录、第二宿主中心会话复用、刷新后的会话恢复、本域登出、认证取消/失败显示与手动重试。协议服务沿用各模块已验证的参考服务，兼容测试只重复必要的代表路径。
- 记录 Node、npm、框架、Vite、浏览器和 SDK 精确版本，以及运行命令、截图或页面状态、控制台/构建错误。版本结论只覆盖实际测过的组合。
- 对自定义会话响应和回跳参数名至少各用一个宿主示例验证，证明业务轻微差异只需配置，无需改 SDK 源码。

## 边界与风险

- Webpack、Vue 2、React Native、微前端容器、跨源 API、SSR 全流程、所有路由库和所有浏览器版本不在本模块的兼容承诺内；若发布需覆盖，另列测试矩阵。
- 本机参考后端通过不代表生产 IdP/SP、CDN、反向代理或业务权限系统通过。跨站 Cookie、HTTPS 和部署拓扑需在真实宿主及发布准备阶段验证。
- 若实际安装暴露 ESM、类型、Vite 5 或浏览器差异，先保留失败证据并修复公共包/示例；不得通过引用 monorepo 源码绕过包问题。

## 验收标准

- Vue 3.4.0 和锁定版本的 React 均从**打包产物**安装同一 SDK，在 Vite 5.0.0 开发与生产构建中成功导入根入口和三个已验收的协议子路径；无需 Webpack 专属配置。
- 两个宿主的浏览器代表流程完成登录、刷新恢复、中心会话复用、本域登出及失败后手动重试，状态与宿主会话接口一致且无导航循环。
- 一项会话响应映射和一项回跳参数名变化通过配置接入；公开类型检查、产物内容和运行时依赖边界通过。
- 兼容矩阵清楚列出实测版本、浏览器、命令、通过与未验证项，不把“构建通过”单独当作端到端通过。
