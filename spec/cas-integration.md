# cas-integration：宿主后端 CAS 票据登录

## 目标

业务应用使用同一 SDK 包的 CAS 子路径，通过已有宿主后端接入统一 CAS 认证中心。首次登录后，第二个宿主复用中心会话取得自己的 Service Ticket；各宿主验票并建立独立本域会话。首版只支持票据落在宿主后端回调入口，浏览器 SDK 不接收或验证票据。

## 三方职责

| 参与方 | 必须提供或完成 |
| --- | --- |
| CAS 认证中心 | `/login`、中心会话 Cookie、针对已登记 `service` 签发一次性且有时效的 Service Ticket，以及 `/serviceValidate` 或 `/p3/serviceValidate` 等约定验票端点；拒绝未登记服务和无效票据。中心 `/logout` 与 SLO 为额外能力。 |
| 宿主后端 | 同源登录入口、固定并登记的回调 `service`、回调关联与安全回跳、服务端验票、会话查询和本域登出。验票时使用与签发时一致的 `service`，解析实际 CAS 响应并只在成功后创建 HttpOnly 本域会话；拒绝错误服务、过期或重放票据。 |
| 前端 SDK | 查询本域会话；未登录时带同源目标页面顶层导航到宿主 CAS 登录入口；返回后恢复状态，区分未登录与故障；调用本域登出。SDK 不构造中心 `/login?service=...`、不读取 `ticket`、不调用验票端点。 |

## 前端配置与交互

1. 业务方导入 `/cas` 的 `casAdapter`，配置同源 `loginEndpoint`。默认用 `returnTo` 传目标页面；宿主参数名不同可配置 `returnToParam`。会话与登出接口沿用公共 `createSSO` 配置。
2. `ensureAuthenticated` 查询本域会话。明确未登录且尚未尝试自动登录时，SDK 导航到宿主登录入口。宿主保存回跳目标和回调关联信息，再把浏览器重定向到 CAS `/login?service=宿主回调`。
3. CAS 中心依据自己的 Cookie 决定是否要求用户登录，并将 Service Ticket 导向原 `service`。宿主后端用同一 `service` 向中心验票，成功后创建自己的会话 Cookie，最后回到业务目标页面。SDK 重新查询宿主会话。
4. App B 重复这条流程，中心会话可免去再次输入凭据，但 B 必须取得并验证自己的票据、创建自己的本域会话。`logout()` 默认只使当前宿主会话失效，不保证中心会话或其他宿主同步退出。

交互时序沿用 [五协议调研中的 CAS 图](../docs/SSO_SDK_方案调研.md)；CAS `service`、验票端点及一次性票据语义以 [Apereo CAS 3.0 协议规范](https://apereo.github.io/cas/7.3.x/protocol/CAS-Protocol-Specification.html) 为准。`/serviceValidate` 与 `/p3/serviceValidate` 的选择由宿主后端与目标中心约定，前端配置不暴露该差异。

## 失败与安全边界

- SDK 与宿主后端分别限制回跳目标；宿主必须登记并固定 `service`，不能直接把任意浏览器输入拼成中心允许的服务地址。
- 票据缺失、过期、服务不匹配、重复使用、中心验票故障或宿主回调关联失败时，不得建立本域会话。宿主应给业务页面或会话接口可辨识的失败结果；SDK 不进入自动跳转循环，用户可主动重试。
- 中心会话过期后，尚无本域会话的第二宿主应重新要求认证。已有宿主本域会话的有效期由宿主后端控制，不能从中心 Cookie 状态推断。
- CAS `renew`、`gateway`、代理票据、前端路由接收票据、中心 `/logout` 和单点登出通知均不纳入首版 CAS 适配器；若业务确有需要，另行定义后端契约与测试，不能仅靠前端开关声称支持。
- 本机简版夹具的固定 XML 字符串判断仅用于交互测试，不能作为生产宿主的 XML 验票实现。

## 验收标准

- 单元测试验证 `/cas` 子路径、同源宿主登录入口、回跳参数配置与公共登录防循环行为。
- 简版双宿主测试验证一次中心登录、两张不同票据、两次宿主后端验票和独立本域会话；拒绝错误 `service`、过期票据、回调重放和非法回跳。
- 使用真实 CAS 参考提供方或独立实现，验证其登录、签发与验票语义，至少覆盖双宿主中心会话复用、错误服务、重放、过期与认证失败；记录提供方版本、配置、环境和实测结果，不以简版夹具替代真实互操作。
- 在真实浏览器验证首次登录、切换第二宿主、本域登出后恢复及失败时可见状态。Vue/React 与 Vite 的完整兼容结论归 `host-compatibility` 模块。
- 生产 CAS 中心和真实业务宿主的接入，以及全局单点登出，留到发布准备时单独确认；本模块的通过只证明当前测试环境内的能力。
