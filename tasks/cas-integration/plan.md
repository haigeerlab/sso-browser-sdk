# cas-integration 实施计划

依据：[CAS 模块 Spec](../../spec/cas-integration.md)。沿用无框架 SDK 核心、`/cas` 子路径和宿主后端会话模式；认证中心与宿主后端只放在私有测试工作区。

## 切片 1：核对现有能力

- 核对 CAS 适配器、公共 API、简版双宿主夹具和测试。验证已有的登录、`service` 绑定、一次性验票、过期票据与非法回跳；把尚未证明的中心会话过期、失败反馈和真实互操作列入验证记录。
- 运行现有 CAS 集成测试和 SDK 单元测试，保留原有行为基线。

## 切片 2：补齐简版异常路径

- 先写失败测试，再用最小夹具改动覆盖中心会话过期后第二宿主重新登录、认证失败、缺失票据或错误回调时不得建立本域会话。必要时让测试宿主把失败带回业务页面，验证 SDK 防循环及手动重试。
- 验证命令：`node --test tests/integration/cas-fixture.test.mjs`；不得把固定 XML 字符串判断称作真实验票实现。

## 切片 3：独立 CAS 实现互操作

- 优先使用 PyPI 的 `django-cas-server` 固定版本构建测试专用认证中心，明确 Python 依赖、测试账号、已登记服务和临时数据。该服务与现有自制夹具分开运行；不进入 npm 发布包。
- 编写宿主后端交互测试，核对真实提供方的 `/login`、Service Ticket、`/serviceValidate` 或 `/p3/serviceValidate`，以及双宿主中心会话复用、错误服务、票据重放、过期与认证失败。若目标实现的配置或本机运行条件不成立，先记录具体阻碍，不以自制夹具代替真实互操作通过。
- 验证命令：独立 CAS 互操作测试脚本；记录版本、协议端点、启动命令与结果。

## 切片 4：浏览器与收尾

- 重新构建 Vue 3.4.0、React 示例（Vite 5.0.0），在浏览器验证首次登录、第二宿主免再次输入、本域登出后恢复和失败状态。
- 运行根目录 `npm test`，更新 SDK README、`tests/README.md` 和本模块 `verification.md`。核对 `spec-guard` 产物与阶段，全部验收满足后勾完 todo，进入 `saml-integration`。

## 环境与边界

- 本机目前有 Python 3.10.7；没有 Docker、Gradle 或 Maven，Java 为 18。真实提供方采用独立 Django CAS 实现是测试策略，不等同于生产目标 CAS 中心。安装固定版本到隔离虚拟环境，保留可重建命令，不修改全局 Python 环境。
- CAS `renew`、`gateway`、代理票据、前端票据回调与全局单点登出均不在本模块实施范围。
- 每一切片完成后记录验证结果；失败时保留失败用例并定位原因，不放宽服务绑定或一次性验票要求。
