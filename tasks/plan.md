# SSO 前端 SDK 实现计划

> 历史原型计划。项目现已启用 Spec Guard；后续任务以 `spec/CAPABILITY-MAP.md`、`spec/<module-id>.md` 和 `tasks/<module-id>/` 为准。本文件不再作为当前模块计划。

状态：执行中。依据：[SSO SDK 方案调研](../docs/SSO_SDK_方案调研.md)。

## 目标

交付一个无框架依赖的浏览器 SDK 包。宿主选择 OIDC、CAS 或 SAML 适配器，配置认证中心与宿主后端的必要入口，就能接入统一登录、会话恢复和登出。协议代码不复制到业务项目；前端 SDK 不替代宿主后端的验签、验票或 API 鉴权。WS-Fed 与 Negotiate 保留扩展边界，待前三种的核心契约稳定后实现。

## 已确定的架构

- 一个 npm 包，公共核心加按需导入的协议子路径。五种后端会话模式的前端入口已实现；协议互操作支持范围由真实提供方验证决定。
- 业务可配置端点路径、宿主响应映射和页面导航；安全必需的协议语义不可通过配置关闭。
- 宿主已有后端；认证回调和本域会话由宿主后端负责。OIDC 浏览器公开客户端作为后续独立模式，不阻塞首版的后端会话模式。
- 核心使用显式状态：`unknown`、`checking`、`authenticated`、`unauthenticated`、`error`。网络错误不能当作未登录。
- 使用 npm workspaces Monorepo：`packages/browser-sdk` 是唯一计划发布的包；`apps/compat`、`services/protocol-fixture` 和 `tests/integration` 留在仓库用于每次修改后的回归，不随 SDK 发布。简版夹具用于 SDK 交互验证；真实协议互操作单独验收。

## 依赖顺序与任务索引

详细验收与验证命令记录在 [todo.md](todo.md)。

1. 冻结公共 API、宿主会话响应与协议适配器接口。
2. 建立包入口、构建和无框架测试底座。
3. 实现公共会话状态、事件、回跳和防循环逻辑。
4. 完成 OIDC 后端会话模式的浏览器闭环与夹具测试。
5. 完成 CAS 票据模式的浏览器闭环与夹具测试。
6. 完成 SAML 后端回调模式的浏览器闭环与夹具测试。
7. 在真实协议提供方与目标浏览器中验证前三种模式。
8. 加入 Vue、React 接入示例并验证 Vite 5.0.0；Vue 目标版本为 3.4.0。
9. 验证已导出的 WS-Fed、Negotiate 前端入口与真实后端／域环境；如有协议专属前端差异再扩展适配器。
10. 整理兼容矩阵、使用文档与发布包检查；发布动作单独执行。

## 检查点

- 任务 1–3：公共状态和配置契约可通过测试独立验证。
- 任务 4–6：三种协议的 SDK 集成流程及失败路径可复现。
- 任务 7–8：真实提供方、浏览器和宿主框架的支持范围有实测记录。
- 任务 9–10：五种协议的实现范围及尚未覆盖环境明确记录，包可用于约定范围内的项目。

## 主要风险与处理

| 风险 | 处理 |
| --- | --- |
| 只有简版服务通过，误判协议兼容 | 每种协议还需真实提供方互操作；Negotiate 需真实域环境 |
| 宿主后端响应形态不同 | 限定在会话映射与入口配置层适配，不放宽协议安全规则 |
| 登录循环或故障时误跳转 | 区分未登录与网络错误，记录单次自动恢复尝试 |
| 跨域 Cookie 与浏览器差异 | 使用顶层跳转；在目标浏览器中做实际验证 |
| 五种模式一次性实现导致核心接口反复重写 | 五种后端会话入口共用一段跳转代码；逐协议做后端和浏览器验证 |

## 当前无阻塞的假设

- “VOE”按 Vue 理解。
- 验证顺序为 OIDC → CAS → SAML → WS-Fed → Negotiate；五种后端会话入口已导出，但未经真实互操作的协议不标记为生产支持。
- 已知最低兼容目标为 Vite 5.0.0、Vue 3.4.0；React 示例采用 19.3.0。webpack 按用户要求暂缓。
- 实际 npm 包名、发布组织和发布凭据尚未确定；本地开发使用临时包名，发布前再定。
