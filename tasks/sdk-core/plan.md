# sdk-core 实施与追认计划

依据：[sdk-core Spec](../../spec/sdk-core.md)。本模块已有原型代码；先按 Spec 逐项核对，再以测试和打包结果决定是否完成，不因旧清单的勾选状态自动认定通过。

1. **契约核对**：检查 `packages/browser-sdk/src/index.ts`、`redirect.ts` 与公开类型，确认状态、错误、回跳、自动登录和登出边界与 Spec 一致。验证：形成逐项核对结果；缺口只修改本模块代码。
2. **行为验证**：运行 SDK 构建与单元测试，并在 Node 环境导入包根入口。验证：测试通过，导入不触发浏览器全局变量错误。
3. **包边界验证**：预览 npm 包内容，检查只有公开入口、类型和文档，不含宿主示例及测试服务。验证：打包清单与 Spec 一致。
4. **模块收尾**：记录已验证和未验证范围；只有本模块验收满足后才勾完 todo，再推进 OIDC 模块。真实认证中心互操作、Vue/React 浏览器接入和全局登出留给对应后续模块。

本计划不发布 npm 包，也不改变认证协议的后端职责。

## 联调回归补充

OIDC 真实参考实现验证中发现：手动登录返回未认证时，核心可能再次自动导航。先补失败单元测试，再调整手动登录尝试标记，最后复跑 SDK 单元与 OIDC 互操作测试；完成后关闭本模块补充任务。
