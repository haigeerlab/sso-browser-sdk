# wsfed-integration 实施计划

依据：[WS-Fed 模块 Spec](../../spec/wsfed-integration.md)。前端只导航宿主同源入口；WS-Fed 令牌与信任验证属于宿主后端。

## 切片 1：基线与独立环境预检

- 核对 SDK `/wsfed` 入口与现有公共测试；确认可运行的独立 STS/RP 产品、版本、令牌类型、安装及信任配置。
- 验证：记录工具链和独立实现启动结果；不能运行时保留明确的实验状态。

## 切片 2：简版双宿主交互

- 先写失败用例，再实现固定 realm/reply、一次性 `wctx`、中心登录/复用、POST 响应、取消和失败反馈。
- 验证：非法回跳、参数篡改、响应过期/重放、不建立错误会话、两个独立宿主会话与本域登出。

## 切片 3：独立 WS-Fed 互操作

- 启动与简版夹具独立的 STS/RP；使用签名 SAML 令牌与固定信任证书，验证双宿主、错误 realm/受众、过期/重放、中心会话和登出。
- 验证：保留可复现配置和运行记录。若无法搭建，标注未验证，不能宣称正式协议支持。

## 切片 4：浏览器和收尾

- Vue 3.4.0 与 React 示例接入 WS-Fed 模式，使用 Vite 5.0.0 构建，并在真实浏览器走首次登录、B 复用、刷新、登出、失败后重试。
- 运行全量测试、类型/包内容与 Spec Guard 检查；更新验证记录和对外支持状态。

## 边界

- 首批只做 RP 发起的 Web Passive POST 响应；令牌类型以独立环境为准。无 Webpack 要求。
