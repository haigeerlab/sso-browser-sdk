# release-readiness 实施计划

依据：[首版发布准备 Spec](../../spec/release-readiness.md)。本模块交付**可审阅的发布候选结论**，不在目标 registry 执行发布。原型包名与 `private` 状态保持，直至发布目标和命名权确定。

## 切片 1：证据与基线

- 汇总 OIDC、CAS、SAML、宿主兼容的已通过证据，核对当前包导出、版本、许可证、仓库/CI 状态与未验证范围。
- 产出逐项可复测的支持矩阵；不把简版夹具和独立参考实现写成生产 IdP/SP 验收。
- 验证：检查各模块 `verification.md`、包清单与实测命令，找出缺失的浏览器版本、真实宿主等发布门槛。

## 切片 2：接入与包边界

- 整理一份业务宿主前后端接入清单，按三个正式支持协议列出中心、宿主后端与前端 SDK 的责任及接口、安全要求、错误/登出语义。
- 核对根入口、协议子路径和类型；明确 WS-Fed/Negotiate 为实验入口，避免文档暗示首版协议互操作已通过。
- 验证：从实际 tarball 隔离安装、Vite 5/Vue 3.4/React 示例和包文件列表复测。

## 切片 3：安全与发布检查

- 运行当前依赖审计，区分 SDK 运行时、示例/测试开发链告警；依据权威公告和当前依赖树记录影响、可用修复与用户锁定 Vite 5.0.0 的冲突。
- 建立可重复的发布检查表，写清包名、registry、版本、许可证、Git/CI、精确浏览器版本和真实业务宿主等通过条件与待办。
- 验证：完整 `npm test`、`npm pack --dry-run --json`、`npm audit --json`、Spec Guard 产物检查。仅对已解决项目打勾。

## 停止条件

- 缺少包名/registry/权限或真实宿主时，完成本机候选包和阻断清单，不自行改成对外可发布状态。
- 安全审计若涉及锁定的 Vite 5.0.0，先量化具体依赖路径与使用场景；没有用户授权不改变其兼容基线或宣布风险接受。
- 实际发布需在目标、版本、tarball 与证据齐备后作为单独可审阅步骤。
