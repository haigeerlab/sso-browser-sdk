# ADR-001：开发者文档站与接入验收设计

状态：Accepted。日期：2026-10-07。用户对设计、大纲和模块安排回复“继续”。

基准：`main`，`8868268ff05314724f25ceb00706827ef1433936`。

## 背景与目标

现有 SDK README、接入指南、协议调研及模块验证记录分散，适合了解实现，但还没有一条首次使用者可以完整执行的接入路径。本轮主要交付文档站、SDK 包 README 和经过验证的代码示例。

成功标准：开发者从包 README 进入文档，判断自己的后端是否符合契约，安装当前可获得的包产物，选择协议及框架，完成配置和登录、会话恢复、退出与失败重试，并知道如何核对后端和定位错误。每个“已验证”声明必须链接具体证据。

目标读者：接入已有认证后端的前端开发者，以及负责补齐宿主接口的后端开发者。默认中文，保留 API 和协议的标准英文名称。

## SDK 的准确定位

当前 SDK 是浏览器中的后端会话接入层。五种协议适配器生成同源宿主登录 URL；协议处理由宿主后端完成。前端查询本域会话、导航登录、订阅状态、防止自动跳转循环并发起本域退出。

认证中心支持 OIDC/CAS/SAML，并不自动意味着 SDK 能直接接入：业务宿主还需要会话查询、同源登录入口、服务端协议回调和登出接口，并按契约建立本域会话。前端不会处理授权码换取、票据验证、断言验签或 Kerberos 协商。

完整性评估必须针对这个边界：是否完整实现所声明的后端会话接入，不能据此宣称它是浏览器原生协议客户端或生产认证服务。

## 框架决策（拟定）

采用 VitePress `2.0.0-alpha.20`。初始建议为稳定版 1.6.4；用户随后指定 2.0.0，npm 查询确认正式 2.0.0 未发布、next 为 2.0.0-alpha.20，用户明确确认使用并锁定该预发布版本。安装前后核对 Node 22.22.0 构建、依赖审计和兼容宿主版本，不跟随无约束的 next/latest。

理由：Markdown 内容可静态构建；默认主题提供导航、侧栏、页内目录、代码复制和本地全文搜索；可从真实源文件引入代码片段，让页面与受验证的示例共用来源。采用默认主题和少量品牌样式，优先保证阅读和复制代码体验。

比较：Docusaurus 的 React/MDX 与多版本文档能力有价值，但本轮只有一个未发布候选，不需要多版本站点、博客或复杂插件。自建 Vue/React 网站还需自行维护目录、搜索和代码展示，对当前交付没有必要。

## 目录与维护方式

拟新增私有工作区 `apps/docs`，站点内容放在该目录，工作区只维护文档构建依赖；保留 `apps/compat` 的既有测试版本。检查安装后的依赖解析，不能因为文档依赖改变原有宿主的实测版本。

根目录提供 `docs:dev`、`docs:build`、`docs:preview` 和文档示例验证命令。文档站依赖、页面和测试不进入 SDK tarball，也不加入 SDK 的运行时依赖。

可复制的最小完整示例收在 `apps/docs/examples`，页面直接引入源文件。示例区分两种用途：业务接入使用可替换的 `/sso/*` 契约；运行现有 Demo 使用真实的 `/app-a/auth/*`、`/app-b/auth/*` 路由。两者不能混用。

现有 `docs/` 中文资料保留原链接，接入指南作为站点入口与职责摘要；研究文档和验收历史保留为补充资料，不把历史状态复制成当前支持结论。

站点先在本机可预览，输出可部署静态产物，并验证根路径与仓库子路径的资源和链接。正式托管可以使用 GitHub Pages；域名、远端部署和启用自动发布不包含在本轮设计确认中。

## 每个协议页面统一格式

1. 适用条件与支持状态。
2. 浏览器、宿主后端和认证中心的流程与分工。
3. 后端/认证中心需要准备的端点、登记参数、响应与协议检查。
4. 可以直接使用的前端配置，标明替换位置和回跳参数。
5. 与仓库参考实现的真实接口对应关系。
6. 完整 Demo 启动与操作步骤，描述每一步预期页面/HTTP 结果。
7. 失败定位与正式部署差异，链接验证证据和协议官方资料。

不将简版夹具的未签名响应当作协议实现，不把 Node/Python/Java 参考服务包装成生产部署模板。此轮复用现有后端示例，不新增不同语言的生产认证后端。

## README 分工

`packages/browser-sdk/README.md` 面向包使用者：定位与前提、当前 tarball 安装方式、无占位函数的最小接入、框架/协议入口、后端最小接口、支持范围和文档链接。正式 registry 安装只能在包实际发布后添加。

根 `README.md` 面向仓库使用者：文档站入口与启动、仓库结构、Demo、开发回归和包构建。详尽指南以站点为主，两个 README 保留必要摘要。尚未上线前使用有效的仓库页面链接和本地启动说明，不声称线上文档已部署。

## 本次核对已发现的文档缺口

- 原接入指南用 `renderAuthState`/`showLoginError` 等未定义函数表示业务代码，不能按“复制完整运行”验收。
- 包仍为 `private: true`、`0.0.0`，安装说明必须给出真实可执行的 tarball 路径与构建顺序。
- 业务示例的 `/sso/*` 与仓库参考服务的 `/app-*/auth/*` 路由不同，必须显式对照。
- SDK 不主动解析 `ssoError` 查询参数；原始协议错误需要业务页自己展示。防循环产生的 `error` 不能描述为 SDK 已解析后端错误码。
- `ensureAuthenticated()` 未登录时导航并返回未登录结果，不能描述为 Promise 等待认证中心完成后直接返回已登录用户。
- 部分历史文档中的 WS-Fed/Negotiate、远端、许可证和 CI 状态已过时，应保留历史语境并把当前结论指向新的支持矩阵。

以上是已核实的文档候选问题，不是整体代码审查的完整结论。

## 验收与开发者视角审阅

| 验收层 | 执行方式 | 通过标准 |
| --- | --- | --- |
| 站点 | 构建、链接/锚点检查、根路径与子路径预览 | 导航和资源有效；没有通过忽略死链让构建通过 |
| 文档代码 | 从实际 tarball 隔离安装，编译文档引用的 TS/Vue/React 源文件 | 导出、类型、路径正确；业务示例有完整上下文且无需工作区软链接 |
| 前后端 | 按协议页面给出的映射和启动步骤，运行已有参考服务及对应流程 | 会话/登录/回调/登出匹配；成功、失败、重试与独立会话的预期一致 |
| 网页自验 | 浏览器阅读站点、搜索、移动布局和复制示例；运行 Vue/React 示例 | 内容可找到、代码可读；示例完整呈现登录、会话恢复、退出和失败反馈 |
| README 与包 | 比对 API 和示例、检查 npm pack 内容、已有 SDK 回归 | README 与页面一致；站点不进入 SDK 包，不改变 SDK 运行时依赖 |
| 审阅记录 | 按首次使用者阅读路径记录步骤、结果和问题 | 报告已验证/待环境/缺陷；不把本机结果等同生产验收 |

最小阅读路径：包 README → 接入前检查 → 安装 → 选择框架 → 选择协议 → 核对后端接口 → 登录/刷新/第二宿主/退出 → 失败重试。执行时只补与文档验收有关的检查，不重复泛扫已完成模块。

SDK 完整性审阅范围是公共 API、五个入口、前后端 HTTP 契约、Vue/React 示例和既有互操作证据。发现源码缺陷时单独记录根因、影响和复现，不用文档绕过，也不在本轮默默扩大成 SDK 重写。正式生产认证中心和企业域条件仍需业务方提供。

## 分阶段推进与待确认项

设计确认后，正式计划拟放在 `tasks/developer-docs/plan.md` 与 `todo.md`，验收记录放在同目录。实施分为站点骨架、接入内容/README、可执行示例、开发者验收与修订四个切片。

当前 Negotiate 等待企业域验收，拟用独立模块 `developer-docs` 管理本轮工作，依赖 `sdk-core`、`release-readiness`、`wsfed-integration`，插在 `wsfed-integration` 之后、`negotiate-integration` 之前。文档站只记录 Negotiate 实验边界，不依赖其企业验收完成。原有两项未完成验收保持不变。

已确认：VitePress、中文大纲、私有文档工作区、开发者验收范围，以及通过 `--interrupt` 插入独立文档模块。正式范围见 `spec/developer-docs.md`，执行进度见 `tasks/developer-docs/`。

后续第一步：按用户评审调整设计，完成模块登记和 Spec 评审，再生成正式计划。各实施切片验证通过后继续；最终浏览器自验及报告完成后交给用户审阅。远端发布或实际业务环境缺失是独立检查点。
